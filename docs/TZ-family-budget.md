# ТЗ: семейный бюджет (обмен отчётами о расходах)

Дата: 23.09.2026
Основание: идея владельца — жена в конце месяца делится своими расходами, у мужа они учитываются и показывается общий расход семьи.

## 1. Что делаем и чего не делаем

**Делаем.** Участник (жена) отправляет свод своих расходов за месяц одним файлом через «Поделиться». Получатель (муж) открывает файл у себя, и в отчёте появляется режим «Семья» с общим расходом.

**Не делаем.** Никакого облака, сервера и аккаунтов. Приложение работает офлайн и не имеет разрешения на интернет (`AndroidManifest.xml`, блок Permissions). Обмен — только файлом, как у резервной копии.

**Решения владельца (приняты):**

1. Передаются только расходы: общая сумма за месяц и разбивка по категориям.
2. Один участник — партнёр.
3. Общий расход виден только на экране «Отчёт».
4. Передача — файл через системное «Поделиться».

## 2. Главное правило

**Деньги партнёра никогда не попадают на счета пользователя.** Семейные данные — отдельная ветка состояния, которая не влияет на:

- счета, доступный остаток, подушку, капитал, садаку;
- дерево и прогресс цели;
- советника («Сейчас стоит») и лимиты по категориям;
- виджет на рабочем столе.

Причина: это чужие деньги. Если подмешать их в баланс, советник начнёт предлагать платить долг из денег, которых у пользователя нет.

## 3. Формат файла

Расширение `.mcfamily`, внутри JSON:

```json
{
  "kind": "my-capital:family-report",
  "v": 1,
  "sender": { "id": "<16 hex>", "name": "Аиша" },
  "monthKey": "2026-09",
  "currency": "RUB",
  "expensesTotal": 4500000,
  "categories": [
    { "category": "Еда", "amount": 1800000 },
    { "category": "Транспорт", "amount": 600000 }
  ],
  "exportedAt": "2026-09-30T18:20:00.000Z"
}
```

- Суммы — в минорных единицах, как везде в приложении.
- `sender.id` — случайный идентификатор, который создаётся при первой отправке и хранится в защищённом хранилище (`FAMILY_SENDER_ID_STORAGE_KEY`, рядом с `BACKUP_SECRET_STORAGE_KEY`).
- Подписи нет намеренно. Проверить подлинность без общего секрета невозможно, и делать вид, что файл «проверен», нельзя. `sender.id` нужен только для одного: если у уже добавленного участника вдруг приходит файл с другим `id`, приложение предупреждает «Файл пришёл с другого устройства».
- Категории — те же строки, что видит отправитель. Без операций, дат, счетов и остатков: в файле не должно быть ничего, кроме месяца, валюты, итога и категорий.
- Пароль в первой версии не спрашиваем. Экран отправки прямо предупреждает: «В файле — суммы твоих расходов за месяц. Отправляй только тому, кому доверяешь». Шифрование можно добавить позже, переиспользовав `encryptBackup` и диалог пароля.

## 4. Состояние и хранение

Новые поля состояния (persist, бэкап, миграции — как у остальных):

```js
familyMember: { id, name, senderId, currency, addedAt } | null
familyReports: [{ monthKey, currency, expensesTotal, categories: [{ category, amount }], exportedAt, importedAt }]
```

- Один участник: `familyMember` — объект или `null`.
- `familyReports` отсортированы по `monthKey` убыванию, хранится не больше 24 месяцев (старые отбрасываются при импорте).
- **Идемпотентность.** Ключ — `monthKey`. Повторный импорт того же месяца заменяет запись, а не добавляет вторую. В подтверждении так и сказано: «Отчёт за сентябрь уже есть, заменить?» с обеими суммами.
- Санитизация в `sanitizeImportedState`: неизвестные поля отбрасываются, суммы приводятся через `toImportedMinorAmount`, отрицательные — в 0, категории — непустые строки.
- Валидация в `backupSchema.js`, чтобы семейные данные ездили в резервной копии.

## 5. Отправка (экран «Отчёт»)

- Новая кнопка «Отправить расходы за месяц» рядом с существующей «Поделиться».
- Выбор месяца: текущий или прошлый (прошлый — по умолчанию, это основной сценарий «в конце месяца»).
- Свод считается по своим операциям через `isReportedExpense`: резерв, садака и движения по долгам в него не попадают — ровно как в отчёте.
- Имя отправителя берётся из нового поля настроек «Моё имя в семейном отчёте». Пусто — спрашиваем при первой отправке.
- Файл уходит тем же путём, что бэкап: `Filesystem.writeFile` + `Share.share` на Android, `navigator.share`/скачивание в вебе.
- Если за месяц нет ни одной траты — кнопка отключена с подсказкой.

## 6. Приём (экран «Настройка» → новый блок «Семья»)

- Кнопка «Добавить отчёт партнёра» открывает выбор файла.
- Первый импорт создаёт участника: имя из `sender.name`, его можно изменить сразу и потом.
- Дальше — список принятых месяцев: месяц, сумма, дата импорта, кнопка «Удалить».
- «Удалить участника» убирает участника и все его отчёты, с подтверждением.
- Отказы с понятным текстом:
  - не тот файл → «Это не семейный отчёт»;
  - валюта не совпадает с валютой пользователя → «Отчёт в USD, а у тебя RUB. Сложить их нельзя»;
  - `sender.id` не совпадает с сохранённым → предупреждение «Файл с другого устройства. Всё равно добавить?»;
  - версия файла новее (`v > 1`) → «Файл сделан более новой версией приложения».

## 7. Отчёт в режиме «Семья»

- Переключатель «Мои / Семья» появляется только когда есть участник хотя бы с одним месяцем.
- Режим «Семья» показывает по выбранному месяцу:
  - «Общий расход» — свои плюс партнёра;
  - «Мои» и «<Имя>» — две суммы и доли в процентах;
  - объединённые категории: одинаковые названия складываются, в строке видно, сколько чьё;
  - подпись «Данные партнёра за <месяц>, получены <дата>».
- Месяцы, по которым отчёта партнёра нет, в режиме «Семья» помечаются: «За октябрь отчёта партнёра ещё нет» — иначе общий расход выглядит заниженным и это вводит в заблуждение.
- Сравнение с прошлым периодом, прогноз цели, норма сбережений и советник в режиме «Семья» не меняются: они про свои деньги.

## 8. Тесты

- Свод своих расходов за месяц: резерв, садака, создание долга и выдача в долг в него не попадают.
- Импорт: создаёт участника; повторный импорт того же месяца заменяет запись и не удваивает сумму.
- Импорт файла в другой валюте отклоняется.
- Импорт файла с чужим `sender.id` требует подтверждения.
- Итоги режима «Семья»: общий расход = свои + партнёра; объединение одинаковых категорий.
- Семейные данные не меняют `availableBalance`, `capital`, `safetyFund`, советника и лимиты.
- Экспорт и импорт резервной копии сохраняют участника и его отчёты.
- Миграция: состояние без семейных полей загружается без ошибок.

## 9. Приёмка

1. У жены: расходы за сентябрь 45 000 → «Отправить расходы за месяц» → файл `.mcfamily` уходит в Telegram.
2. У мужа: открыть файл → появился участник «Аиша», месяц «Сентябрь 45 000».
3. Отчёт → «Семья»: общий расход = его расходы + 45 000, категории объединены.
4. Его баланс, подушка, капитал и советник не изменились ни на копейку.
5. Повторный импорт того же файла: сумма не удвоилась.
6. Экспорт резервной копии и импорт её на чистом приложении: участник и месяцы на месте.
