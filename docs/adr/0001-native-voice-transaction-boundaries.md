# ADR-0001: Границы нативного голосового ввода

- Статус: принято
- Дата: 2026-10-26

## Контекст

Голосовой ввод с Android-виджета должен работать без открытия основного интерфейса. Для этого нативная часть самостоятельно читает локальное состояние, разбирает фразу, применяет финансовую операцию и сохраняет результат. Раньше распознавание, разбор команды, финансовые расчёты и AES-GCM-хранилище находились непосредственно в Activity. Это затрудняло тестирование и создавало две копии кода шифрования.

## Решение

Разделить нативный сценарий на пять границ:

1. `VoiceExpenseActivity` управляет разрешением микрофона, сообщениями пользователю и обновлением виджета.
2. `OnDeviceSpeechService` владеет жизненным циклом строго локального `SpeechRecognizer` и возвращает стабильный код результата. Обычный системный распознаватель не используется, потому что он может отправлять аудио на сервер.
3. `VoiceCommandParser` превращает текст в структурированную команду: тип операции, сумму, категорию и счёт.
4. `VoiceTransactionService` применяет доход или расход к финансовому состоянию и обновляет связанные итоги и историю.
5. `SecureStateRepository` является единственной Android-точкой чтения и записи зашифрованного состояния для `MainActivity` и голосового сценария.

Формат уже сохранённых данных не меняется: используется прежний alias Android Keystore, AES-GCM и прежнее представление `Base64(IV + ciphertext/tag)`. Изменение схемы `localStorage` не требуется.

## Рассмотренные альтернативы

- Оставить всю логику в Activity. Отклонено: высокий риск расхождения правил, дублирования шифрования и регрессий без тестов.
- Открывать основной WebView при каждом нажатии микрофона. Отклонено: нарушает требование быстрого ввода прямо с виджета.
- Запускать скрытый WebView для каждой операции. Отклонено: более тяжёлый и менее предсказуемый путь для фонового сценария Android.

## Последствия

- Разбор речи и финансовые операции покрываются быстрыми JVM unit-тестами.
- Ошибка в UI голосового экрана не требует изменения финансовых правил или шифрования.
- Прошивка без Android on-device `RecognitionService` получает точную ошибку; сетевой fallback не включается автоматически.
- Нативная финансовая логика остаётся отдельной реализацией и должна проверяться контрактными тестами при каждом изменении веб-правил доходов и расходов.
- Реальная проверка микрофона, офлайн-распознавания и виджета всё равно обязательна на Nova 11 и Honor X9d.

## План отката

Откат выполняется возвратом вызовов из `VoiceExpenseActivity` и `MainActivity` к прежней реализации при сохранении неизменными имени preferences, alias Keystore и формата шифротекста. Перед откатом необходимо прогнать нативные тесты и проверить чтение состояния, созданного новой версией: формат данных совместим в обе стороны.
